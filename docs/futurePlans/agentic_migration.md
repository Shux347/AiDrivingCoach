# F1 25 AI Driver Coach: Agentic Architecture Migration

## Overview
This specification outlines the migration from a deterministic, reactive telemetry pipeline to a dual-track agentic architecture. The goal is to retain zero-latency tactical feedback while introducing a strategic, memory-aware LLM agent capable of tool calling and two-way push-to-talk radio communications.

## Architecture: The Dual-Track System
To prevent token-generation latency from ruining real-time apex feedback, the system will split into two parallel execution loops:

1. **Tactical Loop (Existing Phase 4):** Triggers automatically on corner exit. Bypasses the agentic reasoning loop. Uses zero-budget token generation or deterministic logic for immediate delta feedback (e.g., "Braked 10m late into Turn 1").
2. **Strategic Agent Loop (New Phase):** Triggers on pit straights, out-laps, or via Push-to-Talk. Has access to historical telemetry, tyre degradation data, and conversation history via function calling.

## Component 1: Function Calling (Tool Definition)
The LLM orchestrator (Gemini 2.5 Flash) must be provided with Python tools to fetch data dynamically rather than having all session data hardcoded into a single massive prompt.

### Required Tools to Expose
* `get_corner_deltas(lap_number: int, corner_id: int)`: Returns braking point, apex speed, and throttle pickup versus the PB lap.
* `get_stint_summary(stint_id: int)`: Returns average lap time drop-off and tyre wear percentages.
* `check_previous_advice()`: Queries the local database to prevent repetitive coaching on the same corner.

### Implementation Standard
* Use the official `google-genai` Python SDK.
* Define tools using the `google.genai.types.FunctionDeclaration` schema, specifying parameters in an OpenAPI-like JSON structure.
* Pass the wrapped tools to the model using `GenerateContentConfig(tools=[...])`.

## Component 2: Memory & Context (Lightweight RAG)
The agent must recall its own previous advice to avoid repeating instructions lap after lap, mimicking a real race engineer.

* **Data Store:** Implement a lightweight local SQLite database (no need for a heavy vector database yet).
* **Schema:** `[timestamp, lap_number, corner, advice_given, user_response]`
* **Behaviour:** Before generating strategic advice, the agent auto-calls `check_previous_advice()`. If it already warned the driver about Turn 4 trail-braking three laps ago, it must pivot to a secondary weakness or acknowledge the driver's correction.

## Component 3: Push-to-Talk (Two-Way Radio)
The driver must be able to interrogate the agent (e.g., "Why am I losing time in Sector 2?").

* **Hardware Trigger:** Map a steering wheel button (via the `pygame.joystick` or `inputs` Python library) to a callback function.
* **Audio Capture:** Use `PyAudio` to record the microphone buffer while the button is held down.
* **Transcription:** Pipe the captured audio buffer directly to Gemini 2.5 Flash's multimodal endpoint (or a local Whisper model) to transcribe to text.
* **Execution:** The transcription acts as the user prompt in the Strategic Agent Loop. The model reads the prompt, decides which Python tools to call (e.g., fetching Sector 2 deltas), synthesises the data, and replies over the existing `edge-tts` pipeline.

## Migration Phases for Claude
1. **Phase 1 (Tool Wrappers):** Implement the `google-genai` function calling definitions around the existing `corners.py` extraction logic.
2. **Phase 2 (Memory Bank):** Introduce SQLite to log all TTS outputs generated by the LLM, and expose the read function as a tool to the model.
3. **Phase 3 (Audio Ingestion):** Write the joystick listener and PyAudio recorder for the Push-to-Talk feature.
4. **Phase 4 (Agent Integration):** Wire the Push-to-Talk transcript into the agent's prompt, triggering the tool-calling loop and outputting the final response.
